# 资料服务接口

资料源支持单段 HTTP Range，返回 Content-Range 和内容摘要 ETag。If-Match 可以限定本次范围读取的来源版本，版本不符返回 412，越界返回 416。该行为只负责传输，不替接收应用决定领域对象是否完整。

Flux 的 sparse=2 表示 PREV，Quality 的 sparse=1 表示 PAD，Epoch 无稀疏。预览只读目录，尚未把物理记录、虚拟值和时间依据组织成观测收件。

真实 NASA CDF3 单文件由 cdflib 生成且反读确认。Flux 物理记录在 0 和 3，使用 PREV；Quality 同样位置使用 PAD；两者依赖单独时间变量。CDF 不等于 NetCDF，记录目录和数据表示有独立结构。来源原件不需要 Python 运行时，项目全部使用 Node.js。

本地服务的资料入口为 `/files/space.cdf`。`fixtures/ordinary.json` 记录当前可预览的资料；`fixtures/transition.json` 保存资料源连续两个发布日期。调用 `POST /control` 并传入 `{"action":"advance"}` 推进发布日期，`inspect` 返回实际请求记录，`reset` 恢复本地源；控制入口不属于远端标准协议。来源分段、延迟和断连均可用场景条目的 `chunks`、`delayMs`、`disconnect` 配置，不需要依赖实际网络故障。

原件目录采用内容摘要寻址，接收凭据独立记录来源、媒体类型和预览结果。单份资料接收不表示来源范围已经读完，也不推断缺失资料的业务含义。

## 结构化接收

预览只给变量目录；`POST /intakes` 在领取原件的基础上做完整解释，把每个变量按记录号展开成带时间的时间线，每条记录都标注来源，三种情况不会统一当成原始观测：

- `physical`：文件里真实存在的值记录（zVVR），带 `valueOffset` 指向原件字节；
- `previous`：变量 `sparse=2`（PREV）时，缺测时段按前一条物理记录延续得到的虚拟记录，带 `derivedFrom` 指明取自哪条物理记录；
- `pad`：变量 `sparse=1`（PAD）时，用变量自身填充值补上的虚拟记录，填充值来自 zVDR 的 PAD 字段。

变量有各自的记录变化（`recordVary`、`maxRecord`）与维度变化规则，并引用独立时间变量 `Epoch`（CDF_TIME_TT2000，小端纳秒，零基准 2000-01-01T12:00:00Z）。接收时把这些解释依据（稀疏规则、PAD、时间变量、物理记录偏移）与实际取得的记录一起核对，并固化为依据指纹 `basisFingerprint`。

## 时间范围请求

`POST /range-requests` 在已接收会话上按时间窗口选择观测。为理解当前范围所必需的范围外依据（典型是 PREV 虚拟记录所延续的、位于窗口起点之前的物理记录）会读取并登记在 `supporting`，标 `previous-anchor`，但不计入本次新观测；窗口内的结果才放入 `observations`。

## 接收状态与补齐

来源截断或依赖的时间变量缺失时，接收不伪造结果，返回 `status.complete=false` 的可补齐状态：`truncated` 表示结构或变量解释不完整，`missingTimeVariable` 表示时间依据缺失，`reasons` 给出具体原因，已取得的字节仍按内容摘要留存。

`POST /intakes/resume` 按会话锁定的来源版本重取。重取受两层保护，不会凭新文件名悄悄替换旧依据：

1. 携带 `If-Match`，来源版本变化时来源返回 412，会话保留旧依据并要求新建接收；
2. 版本未变但内容摘要与旧依据不一致时返回 409，拒绝同名替换。

只有来源与摘要都一致的同版本重取才允许接续，并累加 `resumeCount`。资料修订（如 `transition` 夹具中 Flux 记录 3 由 15 改为 16，文件名与路径不变）必须通过新的接收会话显式领取。

## 记录框架（本资料实测）

记录头为 12 字节 `[保留 u32=0][长度 size u32][类型 type u32]`，长度含头部；描述符与指针大端，变量数据值按 CDR `encoding` 的字节序（当前为 6，IBMPC 小端）。z 变量由 zVDR(类型 8) 经 firstIndex 指向 zXDR(类型 6)，再由索引项指向 zVVR(类型 7)。稀疏索引项区是 8 字节槽流，记录号槽与值指针槽交错、全 FF 为空槽；非稀疏变量只有一个指向连续值块的项。
